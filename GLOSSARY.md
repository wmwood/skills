# Repository glossary

This glossary records the current library vocabulary. The linked contracts and code define behavior; this glossary provides their canonical names and aliases. Requirements for future features remain in their external approved specifications.

| Term | Meaning and code aliases | Source |
| --- | --- | --- |
| Skill library | This repository's portable skill instructions and supporting resources. Library version is `library_version`/`VERSION`; it is distinct from state schema version. | [README](README.md), [contract](skills/feature-workflow/references/contracts.md) |
| Process skill | An agent role's activation, inputs, authority, procedure, completion and recovery instructions; not an autonomous background service. | [README](README.md), [contract](skills/feature-workflow/references/contracts.md) |
| Feature | A unit of approved product scope with stable `feature_id`, associated tasks and external evidence. | [contract](skills/feature-workflow/references/contracts.md) |
| Original checkout | The user's existing checkout whose branch, HEAD, index, tracked changes and untracked files must be preserved; recorded as `original`. | [contract](skills/feature-workflow/references/contracts.md), [operations](skills/feature-workflow/references/operations.md) |
| Feature workspace | Durable external directory containing ticket, specifications, canonical state and recovery evidence. It is outside all repository worktrees and differs from the feature worktree. | [contract](skills/feature-workflow/references/contracts.md) |
| Worktree | A Git checkout associated with a branch. `feature_worktree` is the integration checkout; each task's `worktree` is its isolated implementation checkout. | [operations](skills/feature-workflow/references/operations.md), [helper](skills/feature-workflow/scripts/workflow.py) |
| Ticket | Immutable approved original feature scope, preserved as `ticket.md` with `ticket_sha256`. | [contract](skills/feature-workflow/references/contracts.md) |
| Specification revision | A full consolidated approved requirements artifact, stored as `specs/0001.md` and increasing revisions; `spec_revision`, `spec_sha256`, `spec_approval`. Earlier revisions remain preserved. | [contract](skills/feature-workflow/references/contracts.md), [helper interface](skills/feature-workflow/references/cli.md) |
| Approval evidence | Explicit human/session evidence and date bound to the relevant artifact digest/revision, or to the cleanup inventory digest. Role labels and helper success do not supply approval. | [contract](skills/feature-workflow/references/contracts.md), [helper interface](skills/feature-workflow/references/cli.md) |
| Canonical state | The feature's authoritative `state.json`. Planner prepares it; Orchestrator is its sole writer after handoff. Worker reports are inputs to that writer. | [contract](skills/feature-workflow/references/contracts.md) |
| Generation | `generation`, the canonical transaction sequence counter. It is not a timestamp or proof of agent liveness. | [helper](skills/feature-workflow/scripts/workflow.py) |
| Task and dependency | A stable task-map ID and its `depends_on` task IDs. Implementation requires completed dependencies; only verified integration permits task completion. | [contract](skills/feature-workflow/references/contracts.md), [helper](skills/feature-workflow/scripts/workflow.py) |
| Task status | `pending`, `implementing`, `review`, `reviewed`, or `complete`. These are workflow states, not proof an agent is currently running. | [contract](skills/feature-workflow/references/contracts.md) |
| Lifecycle | Feature-level `lifecycle`: `active`, `published`, `merged`, `cleanup_pending`, `closed`. Task status and incremental task cleanup are separate. | [contract](skills/feature-workflow/references/contracts.md), [cleanup protocol](skills/feature-workflow/references/cleanup.md) |
| Independent review | A different agent's evidence on the exact task `head` and current specification revision. A passing review permits integration checks, not completion. | [reviewer](skills/independent-code-reviewer/SKILL.md), [helper interface](skills/feature-workflow/references/cli.md) |
| Squash integration | Orchestrator's serialized incorporation of reviewed task changes into one feature commit, with source, parent, tree, specification and successful-check evidence; `integration_commit` and `integration_evidence`. | [contract](skills/feature-workflow/references/contracts.md), [helper](skills/feature-workflow/scripts/workflow.py) |
| Integrated HEAD | `integrated_head`, the last verified feature commit recorded in canonical state. It is distinct from a worker's submitted `head`. | [contract](skills/feature-workflow/references/contracts.md) |
| Checkpoint | Durable intent, result or interruption evidence used to reconcile incomplete operations. A checkpoint or held lock alone does not prove a live worker or a successful operation. | [operations](skills/feature-workflow/references/operations.md), [helper](skills/feature-workflow/scripts/workflow.py) |
| Gate | Independent feature-level evidence under `gates.validation` or `gates.quality`, tied to exact integrated HEAD and specification revision. Missing required checks block a pass. | [contract](skills/feature-workflow/references/contracts.md), [validator](skills/feature-validator/SKILL.md), [quality gate](skills/pre-pr-quality-gate/SKILL.md) |
| Publication and merge | `pr` records inspected draft PR publication evidence; `merge` records separately verified merge evidence. Publication is neither PR approval nor cleanup authorization. | [contract](skills/feature-workflow/references/contracts.md), [cleanup protocol](skills/feature-workflow/references/cleanup.md) |
| Resource manifest | `resources`, keyed by stable resource ID, records exact managed resource identities, owners and purposes. Directory names alone do not prove ownership. | [cleanup protocol](skills/feature-workflow/references/cleanup.md) |
| Cleanup inventory | A concrete resource snapshot bound to `inventory_sha256` and matching `cleanup_authorization`. Per-item results remain durable across interruptions; retained or blocked resources prevent closeout. | [cleanup protocol](skills/feature-workflow/references/cleanup.md) |
| Recovery ref | A durable Git ref under `refs/feature-workflow/` preserving a source commit before authorized worktree/branch removal. It remains after cleanup. | [cleanup protocol](skills/feature-workflow/references/cleanup.md) |
| State schema | `schema_version`/`SCHEMA`, the canonical state's structural compatibility version, distinct from library version. Unknown schemas require explicit compatibility reconciliation before resumption. | [contract](skills/feature-workflow/references/contracts.md), [library update](skills/library-update/SKILL.md) |
| Snapshot | Read-only JSON envelope with independently versioned contract, configured-source results, feature projections and diagnostics. It is an observation of recorded evidence, not execution authority or a live service query. | [snapshot contract](skills/feature-workflow/references/snapshot.md) |
| Visibility eligibility | Retained initial approval and produced-task evidence that permits feature discovery. New interviews/drafts stay private; later revisions do not erase established visibility. Legacy data requires verified existing proof. | [snapshot contract](skills/feature-workflow/references/snapshot.md), [recording interface](skills/feature-workflow/references/cli.md) |
| Work phase | Derived task/lifecycle activity or an explicitly reported operation, distinct from canonical lifecycle. Multiple phases may coexist; a phase does not prove a live process. | [snapshot contract](skills/feature-workflow/references/snapshot.md) |
| Dependency readiness | Derived readiness from existing depends_on IDs and completed dependencies, with named waits. Start eligibility additionally considers recorded approval/control, blockers and other prerequisites; neither dispatches work. | [snapshot contract](skills/feature-workflow/references/snapshot.md) |
| Feedback request | A recorded human question with artifact, affected work, answer/disposition and resolution history. Answering it is not specification or cleanup approval. | [snapshot contract](skills/feature-workflow/references/snapshot.md) |
| Activity freshness | fresh/stale/unknown/invalid relative to actual reported activity and the configured observation threshold. Snapshot generation never refreshes activity, and freshness is not liveness. | [snapshot contract](skills/feature-workflow/references/snapshot.md) |
| Artifact identity | A feature-scoped recorded, logical or recorded-content identity, separate from its current path/URI and availability. Missing identity remains unavailable rather than being invented from a location. | [snapshot contract](skills/feature-workflow/references/snapshot.md) |
