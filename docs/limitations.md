# Known MVP limitations, prioritized

1. **Cooperative authority.** Instructions and state checks are not authentication or a sandbox. Direct filesystem/Git access can bypass helpers; inspect human approval provenance and distinct agent identity. Use environment permissions where appropriate.
2. **Local coordination.** A single canonical writer and local lock/checkpoints are not distributed transactions. Ambiguous interrupted operations require evidence-based Orchestrator recovery; no automatic stale-lock breaking. Cleanup execution journals per-item progress; unresolved errors remain blocked. Docker absence is verified through successful daemon listing before retry reconciliation. Directories are removed only when empty.
3. **Compatibility.** Releases include hashes/version/schema. Unknown schemas/major versions block writer resumption and yield unsupported read results. Schema 2 workspaces can be projected without adoption; absent visibility metadata stays not_recorded. Explicit adoption/limited rollback requires owner coordination, backup and verified bindings under Library Update. No generic migration converter, automatic update, background watcher or global feature registry exists.
4. **Publishing.** Live issue/PR publication requires authorization, authentication and service availability. Local tests do not publish. PR approval/merge remain human-owned.
5. **Agent judgment.** Skills are instructions interpreted by an agent, rather than a self-executing workflow engine. Scenarios validate deterministic safety and contracts; complex product behavior still requires independent review, feature validation and quality assessment against real acceptance criteria.
6. **Platforms.** Writer helpers use portable Python and subprocess Git. The snapshot reader needs Python 3.10+ and standard-library filesystem access only. Callable consumers must disable bytecode before loading the reader; arbitrary default import is outside the supported no-cache bootstrap. Record actual shell coverage; Git Bash syntax checks do not establish Linux execution. Repository hooks/tool availability and symlink/junction privileges vary.
7. **Installation.** The installer creates a new skills root only. Existing collections require reviewed manual copying/backups. Development does not install outside this repository.


8. **Snapshot boundaries.** Snapshots report locally recorded evidence and freshness, not live agent/process/provider state. Missing or inconsistent proof remains unavailable/unknown; historical timestamps and approval are not reconstructed. Partial sources do not hide healthy sources. Initial pre-approval work is excluded, while later waits on established features are visible. Dashboard hosting, UI, live integrations and any consumer-owned cache remain separate from this repository.
